# Gold 标注格式说明（Splitter V2 Stage 2 验收用）

> 目标：**最小、易人工编辑**的人工标准答案格式，用于和程序输出自动对照。
> 只表达结构与关系，不要求标注每一个段落。
> 工具：`app/gold_compare.py`（只读，不实现任何 Stage 2 识别算法）

---

## 1. 文件形态

一个文档一个 JSON 文件：

```json
{
  "doc": "人类可读的文档标识（不参与判分）",
  "notes": ["可选，给标注者自己看的说明", "可以是数组或字符串"],
  "units": [ { ...单元... }, { ...单元... } ]
}
```

`units` **按文档顺序书写**即可（工具按顺序解析锚点）；顺序本身不参与判分。

---

## 2. 单元字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 本文件内唯一。父子/绑定关系都用它引用 |
| `role` | 建议 | 见 §3 角色表。缺省 `body` |
| `level` | 可选 | 章节层级，1 起（`section` 用） |
| `parent` | 可选 | 父单元 `id`。**关系的唯一表达方式** |
| `bind_to` | 可选 | 把「题组」绑定到「共享材料」的 `id` |
| `anchor` | 二选一 | 单元**起始**定位文本：子串匹配（自动归一化空白） |
| `end_anchor` | 可选 | 单元在**该文本之前**结束 |
| `spans` | 二选一 | 显式块序号片段 `[[start,end], ...]`，闭区间 |
| `start` / `end` | 二选一 | 单片段简写，等价于 `spans:[[start,end]]` |
| `must_stay_together` | 可选 | 默认：`question_group` / `shared_material` 为 `true` |
| `note` | 可选 | 标注者备注，不参与判分 |

**定位优先用 `anchor`**（人类易写、与段落号解绑）；块序号会随解析实现变动，
但锚点文本不会。需要精确边界（或未来重排后的多片段）时再用 `spans`。

### 2.1 定位方式（四种，可混用）

| 写法 | 说明 | 适用 |
|---|---|---|
| `anchor` / `end_anchor` | 全局按文档序做文本匹配（子串、空白归一化） | 最省力，首选 |
| `scope` + `anchor` | 在**指定容器内**匹配文本 | **表格单元格内部**结构（见 §2.4） |
| `node` | 直接给节点 id（容器 id = 整个容器） | 精确指定某一段/某张表 |
| `spans` / `start`+`end` | 节点区间；整数 = 顶层块号（向后兼容旧 gold） | 程序输出、重排后的多片段 |

### 2.2 节点 id 语法（表格内部寻址）

```
b{seq}                        body 顶层块
b12.r1c0                      第 12 块（表格）第 1 行第 0 列**单元格容器**
b12.r1c0.n2                   该单元格内第 2 个块（= Cell.blocks 下标）
b12.r1c0.n2.r0c1.n0           该块（嵌套表格）第 0 行第 1 列单元格内第 0 个块
```

- 容器（`body` / 表格 / 单元格）**不是内容**，只提供范围；
  内容节点 = 段落 / 未识别块。
- **端点自动展开**：`spans: [[2,7]]` 仍表示「第 2..7 块里的**全部内容**」，
  其中表格单元格内的段落会被自动包含 —— 旧 gold 写法语义不变。
- 表格的扁平文本只是 rollup，不计入内容统计（避免与单元格内节点重复计数）。

### 2.3 锚点解析规则

1. 锚点按 `units` 顺序解析，游标**只前进不后退**。
2. 因此重复标题（真实讲义常见：「基础稳固」在题目区与答案区各出现一次）
   会自然落到**第 1 次、第 2 次**出现，无需人工加序号。
3. 文本匹配前会归一化：去零宽字符、压缩所有空白。`1.  What` 与 `1. What` 等价。
4. 单元的 `end` 优先取 `end_anchor`；否则取**下一单元起点 − 1**；最后一个单元取文末。
   所以只写起点也能标完 —— 这是人工标注最省力的写法。
5. `scope` 存在时，锚点只在该容器（含其全部后代）内查找。

### 2.4 表格内部结构：推荐写法

真实讲义里大量结构藏在表格单元格内（实测约 38% 的段落；「全文一表」型讲义甚至 100%）。
推荐 **`scope` + `anchor`**，其次才是 `node`：

```json
{
  "id": "toc1", "role": "toc", "node": "b2.r5c0.n8",
  "note": "目录是嵌在单元格里的嵌套表格，整表作为目录区"
}
{
  "id": "k1", "role": "knowledge", "scope": "b12.r1c0",
  "anchor": "知识精讲", "end_anchor": "题型1",
  "note": "同一张表的左上单元格：前半是知识"
}
{
  "id": "g1", "role": "question_group", "scope": "b12.r1c0",
  "anchor": "题型1", "bind_to": "m1",
  "note": "同一张表的左侧单元格后半：题组"
}
```

- `scope` 指向单元格即可表达「**同一张表中，前半部分是知识、后半部分是题组**」。
- 整张表作为整体时：`node: "b12"`（= 该表全部后代内容节点）。

### 2.5 程序结果侧约定

1. **互不重叠**（构成分块序列）；重叠即报 `DUPLICATION`。
2. 层级与绑定用**显式指针**（`parent` / `bind_to`）；
   指针缺失时工具才退化用「同一单元内」的包含关系兜底。
3. **重排用多片段**：`"spans": [["b120","b150"],["b8","b20"]]`。
   顺序变化本身**不判错**。
4. 引用不存在的节点 → `PRED_ANCHOR`（硬错误），
   这样能立刻发现「用了过期块号」这类问题。

## 3. 角色表（role）

| role | 含义 | 判分要点 |
|---|---|---|
| `toc` | 目录区（点线目录等） | 与正文严格区分：判成正文＝目录误当正文 |
| `section` | 章节标题/章节结构节点 | 可用 `level` + `parent` 表达层级 |
| `shared_material` | 共享材料（阅读原文、语篇、图表材料） | 默认**整体不可拆**；可与题组绑定 |
| `question_group` | 完整题组（一组题连同选项） | 默认**整体不可拆** |
| `question_item` | 单题 | 与 `question_group` 互相兼容 |
| `answer` | 答案 / 答案区 | 与 `analysis` 互相兼容 |
| `analysis` | 解析 / 详解 | 同上 |
| `knowledge` | 知识讲授内容 | 与 `body` 界限模糊，判定宽松 |
| `unknown` | 程序未识别但需保留的内容 | 判成正文属轻微降级 |
| `body` | 兜底：普通正文 | 与任何角色都不冲突 |

**兼容性三档**（工具内 `ROLE_RULES`）：

- `ok`：等价，不报。
- `soft`（警告）：结构降级，例如 `section → body`、`answer → body` → 报 `MISSED_STRUCTURE`。
- `hard`（错误）：角色冲突，例如 `toc → body`（报 `TOC_AS_BODY`）、
  `question_group → answer`（报 `ROLE_MISMATCH`）。

## 4. 程序结果的写法

同一套字段，通常用 `spans`/`start-end`（程序天然按块区间输出）：

```json
{
  "units": [
    {"id": "P1", "role": "section", "level": 1, "start": 0, "end": 1},
    {"id": "P2", "role": "shared_material", "start": 2, "end": 7},
    {"id": "P3", "role": "question_group", "start": 8, "end": 20,
     "parent": "P1", "bind_to": "P2"},
    {"id": "P4", "role": "answer", "start": 21, "end": 36, "parent": "P1"}
  ]
}
```

约定：

1. **程序单元应互不重叠**（构成分块序列）；重叠即报 `DUPLICATION`。
2. **层级与绑定用显式指针**表达（`parent` / `bind_to`）。
   指针缺失时工具才退化用「同一单元内」的包含关系兜底。
3. **重排用多片段表达**：把前移的例题写进另一个片段即可，
   例如 `"spans": [[120,150],[8,20]]`。顺序变化本身**不判错**。

## 5. 判定项与问题码

| 问题码 | 含义 | 级别 |
|---|---|---|
| `OMISSION` | 内容遗漏（gold 有、程序未覆盖） | 错误 |
| `DUPLICATION` | 无意重复（程序单元区间重叠） | 错误 |
| `GROUP_SPLIT` | 完整题组/材料被拆开 | 错误 |
| `TOC_AS_BODY` | 目录误当正文 | 错误 |
| `BODY_AS_TOC` | 正文误当目录 | 错误 |
| `HIERARCHY` | 章节关系错误（未声明/父不一致/层不一致/父未识别） | 错误 |
| `UNBOUND` | 共享材料与题目解绑 | 错误 |
| `ROLE_MISMATCH` | 角色硬冲突 | 错误 |
| `MISSED_STRUCTURE` | gold 有但程序未识别（降级为 body） | 错误（完全未覆盖）/ 警告（降级） |
| `MERGE` | 两个独立 gold 单元被合并进同一程序单元 | 警告 |
| `EXTRA_STRUCTURE` | 程序多标的结构（gold 视为 body） | 警告 |
| `EXTRA_UNIT` | 程序多出的单元 | 提示 |
| `GOLD_GAP` | gold 未覆盖的文档内容（**标注缺口，不是程序错误**） | 提示 |
| `GOLD_OVERLAP` / `GOLD_ANCHOR` | gold 自身标注问题 | 提示 |
| `ORDER_CHANGE` | 顺序变化（**按约定不判错**） | 提示 |

**结论**：存在任何「错误」即 `FAIL`；只有警告/提示为 `PASS`。

---

## 6. 判分口径（重要）

1. **顺序变化不判错。** 所有判定都是「身份 + 关系」的集合运算。
   未来允许把完整内容单元整体重排（例题前移、练习下沉）。
2. **完整题组不可拆**：题组/材料的**已被程序覆盖部分**必须落在同一个程序单元内。
   （未覆盖的块由 `OMISSION` 负责，不重复报 `GROUP_SPLIT`。）
3. **共享材料绑定**：程序声明了 `bind_to` 就以声明为准校验；
   未声明则要求材料与其题组落在同一程序单元内。
4. **只统计有内容的块**（文字/图片/OLE/公式/表格文本）；空段不参与遗漏判定。
5. **表格**：`StructDoc` 中表格是独立块，其单元格内容算作该块的内容。

## 7. 命令行

```bash
PY="C:/Users/Administrator/Desktop/工作/讲义生成器/讲义生成器flash版/res/python/python.exe"
T="C:/Users/Administrator/Desktop/工作/jiangyi-generator/app/gold_compare.py"

# 完整对照（生成 markdown 报告 + 可选 JSON）
"$PY" "$T" --doc 讲义.docx --gold gold.json --pred pred.json \
      -o 对照报告.md --json 结果.json

# 只做 gold 自审（检查锚点是否都能解析、覆盖是否有缺口）
"$PY" "$T" --doc 讲义.docx --gold gold.json -o gold自审.md
```

退出码：`0` = PASS，`1` = FAIL（可直接接入 CI）。
