# Splitter：固定 Python 与 API 的可行性评估

日期：2026-10-25。基线：c4 发布分支 `6016a38`；本地 `audit/chrome-layout-20261025`。
范围：源码及既有证据审查。没有修改产品代码、调用模型 API、重新运行全量语料或生成新讲义。

## 结论

固定 Python 可以覆盖结构稳定、标记明确的来源，但现有证据不足以支持它对多学科、不同出版格式的开放资料稳定完成全部语义拆分。不能由“现实现失败”推出“所有离线算法都不可能”；本结论是工程投入判断：不建议继续无限追加标题/题号例外，建议 Python 保留结构保真与验证，模型 API 承担模糊语义判定。

Python 与 API 不是互斥方案。即使接 API，也必须保留 Python 的 OOXML 解析、节点寻址、资源搬运、校验与模板输出。

## 用户澄清

“分栏”指核心 Splitter，不是页面 CSS 或 Word 双栏。用户询问固定 Python 脚本可行性，若不足则考虑恢复 API；此轮是评估，不是上线授权或 API 已验证有效的结论。

## 哪些适合固定脚本

| 工作 | 固定 Python 的边界 | API 的作用 |
|---|---|---|
| 读取段落、表格、样式、题号与资源 | 能做，复杂文本框、合并表格、替代内容仍需专门解析和验证 | 不能补救已经丢失的原文结构 |
| 明确标题下的章节归属 | 可通过规则稳定处理已支持格式 | 通常无需调用 |
| 图片、公式、表格搬运与资源关系 | 应由确定性代码执行；未知关联须保留或复核 | 不应重写原始公式、题干或二进制资源 |
| 缺标题、重复编号、知识与例题交替 | 有些可由结构解决，有些需要上下文语义 | 适合提供边界、角色和归属建议 |
| 题干、选项、小题、共享材料、解析绑定 | 明确标签可规则处理；复杂归属不能只按相邻题号猜 | 可辅助判别，但需完整上下文和独立金标验收 |
| 教师/学生版本对应 | 精确一致部分可匹配；增删、换序和不同排版有歧义 | 提议对应关系，不能把语义相似直接当同题 |
| 无知识区、无测试区如何编排 | 是产品规则，需要明确来源/例题研读/用户选择等策略 | 无法恢复原稿本来不存在的作者意图 |

## 旧 API 不能直接重新启用

`v1.1-stable/res/app/llm_split.py` 文件头写目录分类，但实际 `_impl` 将每段截取150字，要求知识/训练/巩固三块，并用 `type_starts` 每类只保留一个起点。知识→例题→练习→下一知识点这样的多次交替无法表达。输入也没有完整的表格/资源/层级信息。

`selective_llm_split.py` 则只允许从脚本提供的边界候选中选择。真实切点没进入候选集合时，模型没有纠错空间。局部窗口还可能看不到共享材料和远处统一答案。此文件的存在不代表当前1.2已接 API。

因此 API 的成败主要取决于输入和输出契约，不能简单更换模型或打开旧开关。

## 推荐方案

1. Python 先生成有稳定ID的物理节点清单：原文、层级、表格/单元格、编号、样式、图片公式引用及原文顺序；保留支持范围外对象。
2. 先识别自然教学结构，输出可变数量的知识块、例题、练习组、共享材料和答案解析。三栏是最终模板目标，不应反过来强迫原文永远只有两个切点。
3. 已有可靠、经样本验证的规则直接处理；不确定模块交模型。提供全文结构概览和完整相关模块，必要时扩大上下文。允许模型在合法节点中提出新边界，不限于旧候选切点；长文按自然模块分块，保持跨块引用。
4. API 只返回节点ID、角色、边界、父子/归属和待确认项，不生成替代正文。图像/OLE中承载关键含义且文本提取不可见时，必须补可读图像输入或明确不支持，不能让模型猜。
5. Python 检查ID合法、覆盖与重复、顺序、共享材料依赖、图片公式关系及角色来源，再搬运原始XML。结构检查能发现漏块等问题，不能证明语义归属正确；语义正确仍需独立人工标注和验收。模型自报置信度不作为唯一自动放行依据。
6. 教师学生资料分别保真，显式记录对应已验证/未验证。配对不明不能冒充已同步；只有教师原稿时，答案删除必须独立验证，不能复用“模型说是题干”作为安全保证。
7. API异常、输出不完整或语义不明时进入可见复核/原文保留状态，不能把比例兜底冒充理解成功。缓存按源文件哈希、模型与提示/规则版本隔离，记录实际延迟与费用。

JSON输出是实现手段，不是语义正确保证。官方文档支持合法JSON输出：[DeepSeek JSON Output](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)。模型/供应商选择待同样本对照，不使用旧代码注释中的费用估算。

## 有限验证方案与决策标准（建议，非已经执行）

- 不再开启无止境“再补几条规则”。以同一份结构输入比较固定脚本和API辅助方案，避免将输入修复的收益误算成模型收益。
- 先取覆盖知识题号、重复编号、表格嵌套、共享阅读、统一答案、教师学生结构差异的代表样本；区分开发样本与未参与调参的独立留出样本。
- 重用已有33/35主题清单及金标资源，恢复原稿并核对哈希；补充当前未覆盖的新来源。当前仓库 `docs` 只随附4份源DOCX（两组历史成功配对），不足以重跑完整失败语料。
- 分开报告：边界/角色/答案绑定准确性、整份无需修正比例、拒绝/待复核比例、丢题重题和资源错误、端到端生成率、单份成本与耗时。
- 建议初期放行门槛：在声明支持的独立留出集上，整份无需人工修正不少于90%；任何漏题、重题、资源丢失、答案进入学生版均阻断相应版本发布。这是测试集上的门槛，不是对未知输入的零错误保证。
- 若固定脚本仅对特定模板通过，保留该离线快捷路径；若API在留出集提升不显著，不接入生产。若两者都不达标，应收窄支持范围或加入可视化纠错，不能降低完整性检查伪装达标。
